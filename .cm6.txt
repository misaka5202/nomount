fix: patch only the missing struct module fields instead of overlaying kheaders

Overlaying the device kheaders wholesale is not viable: it drags in
include/linux/sched.h and other headers that conflict with the rest of
the tree, failing with

  ../include/linux/sched.h:1223:48: error:
      member of anonymous union redeclares dmabuf_info

Comparing include/linux/module.h line by line against the device copy,
comments stripped, narrows the real difference to a single block:

  #ifdef CONFIG_MITIGATION_ITS
          int its_num_pages;
          void **its_page_array;
  #endif

It sits mid-struct, shifting every field after it, which is precisely
why module_layout is 0xa26bedb1 here and 0xea759d7f on device.

This tree (6.1.134) has no Kconfig entry for MITIGATION_ITS -- it
arrived in a later stable -- so syncconfig would discard the symbol even
if written. Emit the two fields unconditionally instead: the device has
them, so struct module must contain them regardless of how the config is
spelled.

The option only gates these pointers, so unconditional inclusion
reproduces the shipped layout exactly and stops the -ENOEXEC / panic
cycle at its source rather than faking the CRC.
