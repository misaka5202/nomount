ci: overlay device config onto a tree-generated .config

Neither of the two previous approaches can work on their own:

 - `make xxx_defconfig` / olddefconfig reconciles every symbol against the
   tree's Kconfig. The device config carries ~2400 vendor-only options that
   common/ has no Kconfig entry for; the reconciliation cascades and takes
   MODULES / MODVERSIONS / MODULE_UNLOAD down with it, so vmlinux refuses
   to build ("The present kernel configuration has modules disabled").

 - Dropping the device config in verbatim and running syncconfig hits the
   opposite problem: the tree has symbols the device config never recorded,
   Kconfig asks about each one as "(NEW)", and with no stdin it applies
   defaults, which again resets the same critical options.

Generate a self-consistent .config from gki_defconfig first, then overlay
every value the device config specifies (including "is not set" entries)
on top of it. The result is the tree's complete symbol universe carrying
the device's actual values, which is what struct layouts depend on.

Verified locally that the overlay keeps MODULES, MODVERSIONS,
MODULE_UNLOAD and KALLSYMS_ALL enabled. Gates before and after syncconfig
now fail fast if any of them gets reset again.
