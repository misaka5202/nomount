ci: load the device config verbatim instead of via *_defconfig target

`make device_defconfig` reconciles the whole configuration against the
tree's Kconfig before writing out/.config. The device config carries
about 2400 vendor-only symbols that common/ has no Kconfig entry for,
and the reconciliation cascades: MODULES, MODVERSIONS, MODULE_UNLOAD,
KALLSYMS_ALL and FTRACE all came back disabled, so vmlinux refused to
build at all with

    *** The present kernel configuration has modules disabled.

Place the device config directly as out/.config and run syncconfig
instead, which generates include/config/auto.conf without re-deriving
every symbol.

Add an explicit gate on the options that must stay enabled (MODULES,
MODVERSIONS, MODULE_UNLOAD, ARM64) and dump the offending lines on
failure, so a silently reverted config cannot reach the compile step
again.
