ci: overlay the device's own kheaders to fix residual struct layout drift

With the device .config fully applied (verified MODULES, MODVERSIONS,
FTRACE, KALLSYMS_ALL, SYSFS, CFI_CLANG all =y), module_layout still
disagrees:

    device: 0xea759d7f
    ours:   0xa26bedb1   (identical to the value before any config work)

That rules out CONFIG-driven layout changes and points at the type
definitions themselves: the open-source tree is 6.1.134, the device runs
6.1.157, and stable backports in between touched struct module and the
nested types it embeds.

CONFIG_IKHEADERS is enabled on this device, so its own include/ tree is
readable from /sys/kernel/kheaders.tar.xz. Ship it as
device_kheaders.tar.xz and overlay it onto the kernel tree before
building. The step still accepts device_headers_url for rotating it
without a commit, and warns rather than failing when neither is present.

Overlay only replaces files the device also has; tree-only headers stay
untouched so the build does not break on missing internals.
